# Dynamic Rubrics Grading Pipeline

Grading pipeline for LLM-generated dynamic rubrics with two-dimensional scoring (keyword + semantic) and in-memory vector stores.

## Overview

This pipeline extends the standard `grading_pipeline` with support for:

- **Dynamic rubrics** generated by LLMs (from `rubrics_dynamic/yaml/`)
- **Two-dimensional scoring** combining keyword matching and semantic similarity
- **In-memory vector stores** for fast, stateless operation
- **Configurable scoring weights** per criterion (keyword vs semantic balance)

## Key Differences from Static Rubrics

### Dynamic Rubric Fields

Dynamic rubrics include additional fields not present in static rubrics:

```yaml
question_id: q01
total_points: 10
scoring_weights:
  criterion_id:
    keyword: 0.5      # Weight for keyword matching (0-1)
    semantic: 0.5     # Weight for semantic similarity (0-1)
semantic_decay: linear  # Decay function for evidence ranking
semantic_top_k: 5       # Number of evidence chunks to consider
criteria:
  - criterion_id: definition_accuracy
    description: "..."
    points: 3
    evidence_required: true
    evaluation_method: semantic
```

### Two-Dimensional Scoring

Each criterion is scored using both keyword and semantic dimensions:

```
dimension_score = (keyword_weight × keyword_score + semantic_weight × semantic_score) × max_points
```

Where:
- **keyword_score** (0-1): Based on keyword matches in student answer
- **semantic_score** (0-1): Based on semantic similarity of retrieved evidence
- **keyword_weight** and **semantic_weight**: From rubric's `scoring_weights`
- **max_points**: Points allocated to the criterion

See [`CURRENT_GRADING_STRATEGY.md`](../CURRENT_GRADING_STRATEGY.md) for detailed examples.

## Usage

### Command Structure

```bash
uv run python -m grading_dynamic_rubrics.cli grade-question \
    --question q01 \
    --rubrics-config grading_dynamic_rubrics/config/rubrics.yaml \
    --submissions-dir grading_dynamic_rubrics/submissions \
    --sources-config grading_dynamic_rubrics/config/sources.yaml \
    --output grading_dynamic_rubrics/results/q01_results.json
```

**Key differences from static rubrics CLI:**
- ✅ No `--index-dir` flag (in-memory only)
- ✅ No `--index-backend` flag (always in-memory)
- ✅ Points to `grading_dynamic_rubrics/` directories
- ✅ Uses dynamic rubrics from `rubrics_dynamic/yaml/`

### Grade a Question

Grade all submissions for a specific question:

```bash
uv run python -m grading_dynamic_rubrics.cli grade-question \
    --question q01 \
    --rubrics-config grading_dynamic_rubrics/config/rubrics.yaml \
    --submissions-dir grading_dynamic_rubrics/submissions \
    --sources-config grading_dynamic_rubrics/config/sources.yaml \
    --output grading_dynamic_rubrics/results/q01_results.json
```

### Grade a Single Student

Grade one student's submission:

```bash
uv run python -m grading_dynamic_rubrics.cli grade-student \
    --submission grading_dynamic_rubrics/submissions/student_001_q01.yaml \
    --rubrics-config grading_dynamic_rubrics/config/rubrics.yaml \
    --sources-config grading_dynamic_rubrics/config/sources.yaml \
    --output grading_dynamic_rubrics/results/student_001_q01.json
```

### Optional Logging

Add `--log` flag to save detailed logs:

```bash
uv run python -m grading_dynamic_rubrics.cli grade-question \
    --question q01 \
    --rubrics-config grading_dynamic_rubrics/config/rubrics.yaml \
    --submissions-dir grading_dynamic_rubrics/submissions \
    --sources-config grading_dynamic_rubrics/config/sources.yaml \
    --output grading_dynamic_rubrics/results/q01_results.json \
    --log grading_dynamic_rubrics/logs/q01_grading.log
```

### Debug Mode

Add `--debug` flag to see detailed scoring information (useful for troubleshooting):

```bash
uv run python -m grading_dynamic_rubrics.cli grade-question \
    --question q01 \
    --rubrics-config grading_dynamic_rubrics/config/rubrics.yaml \
    --submissions-dir grading_dynamic_rubrics/submissions \
    --sources-config grading_dynamic_rubrics/config/sources.yaml \
    --output grading_dynamic_rubrics/results/q01_results.json \
    --debug
```

Debug output shows:
- Keyword scores and which keywords were found/missing
- Semantic scores from evidence retrieval
- Scoring weights applied
- Combined scores before rounding
- **Warnings for negative scores** (which should never happen)
- Evidence similarity scores

## Implementation Details

### In-Memory Indexes

The pipeline uses in-memory vector stores for:
- **Fast startup**: No disk I/O for loading indexes
- **Stateless operation**: Indexes rebuilt on each run
- **Simplicity**: No persistence management needed

Indexes are built using `grading_pipeline.index_builder_in_memory.build_or_update_dual_indexes_in_memory()`.

### Semantic Decay

The `semantic_decay` field controls how evidence ranking affects scoring:

- **`linear`**: Weight evidence by position (1.0, 0.5, 0.333, ...)
  ```python
  weights = [1.0 / (i + 1) for i in range(len(scores))]
  semantic_score = sum(s * w for s, w in zip(scores, weights)) / sum(weights)
  ```

- **`none`**: Simple average of all evidence scores
  ```python
  semantic_score = sum(scores) / len(scores)
  ```

### Scoring Weights

Each criterion can have custom keyword/semantic weights:

```yaml
scoring_weights:
  definition_accuracy:
    keyword: 0.6  # Emphasize keyword matching
    semantic: 0.4
  illustrative_example:
    keyword: 0.3  # Emphasize semantic similarity
    semantic: 0.7
```

Default is 50-50 if not specified.

## Troubleshooting

### Error: "Question ID not found in rubric config"

**Solution**: Add the question to `grading_dynamic_rubrics/config/rubrics.yaml` and ensure the rubric file exists in `rubrics_dynamic/yaml/`.

### Error: "No submissions found for question"

**Solution**: Create submission files in `grading_dynamic_rubrics/submissions/` with the correct naming pattern: `student_XXX_qYY.yaml`.

### Slow Performance

**Solution**: In-memory indexes rebuild on each run. For large document sets, consider using the persistent ChromaDB backend in `grading_pipeline` instead.

### Different Scores than Expected

**Solution**: Check the `scoring_weights` in your dynamic rubric. Adjust the keyword/semantic balance to match your grading priorities. Use `--debug` flag to see detailed scoring breakdown.

### Negative Scores

**Solution**: This should never happen! If you see negative scores:
1. Run with `--debug` flag to see where the negative value originates
2. Check the debug output for:
   - Negative similarity scores from evidence retrieval
   - Negative keyword or semantic scores
   - Issues with scoring weight application
3. Report the issue with the debug output

## Comparison with Static Rubrics Pipeline

| Feature | Static Rubrics | Dynamic Rubrics |
|---------|---------------|-----------------|
| Rubric Source | Manual YAML files | LLM-generated YAML |
| Scoring Method | Keyword only | Keyword + Semantic |
| Index Backend | ChromaDB (persistent) | In-memory |
| Scoring Weights | Fixed (keyword only) | Configurable per criterion |
| Semantic Decay | N/A | Linear or none |
| CLI Flags | `--index-dir`, `--index-backend` | Simplified (no index flags) |
