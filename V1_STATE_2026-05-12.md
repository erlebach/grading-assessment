# V1 Grading Pipeline — State as of 2026-05-12

## Purpose

Documents the complete v1 pipeline architecture, data flow, input/output schemas, and
benchmark results as of T4.3. Serves as the reference for deciding what detail v2 must
replicate or surpass.

---

| Command | File | Purpose |

## 3. Pipeline Flow (End-to-End)

```
Student answer + question_id + rubric
│
├─ 1. INDEX SETUP  (pipeline.py::setup_grading_environment)
│   ├─ CharacterSplitter (512 chars, 50 overlap) → word_index
│   └─ SentenceSplitter  (256 tokens, 50 overlap) → sentence_index
│
├─ 2. EVIDENCE RETRIEVAL  (retrieval_core/retriever.py)
│   └─ for each criterion with evidence_required=true:
│       ├─ word_index.query(criterion.description, top_k=10)
│       ├─ sentence_index.query(criterion.description, top_k=10)
│       ├─ rerank both with CrossEncoder (ms-marco-MiniLM-L-6-v2)
│       └─ deduplicate → final_top_k=5 spans
│
├─ 3. SCORING  (grading_dynamic_rubrics/pipeline.py::apply_rubric_scoring_dynamic)
│   └─ for each criterion:
│       ├─ keyword_score  = |found_keywords| / |all_keywords|        [0–1]
│       ├─ semantic_score = min(1, |evidence_spans| / semantic_top_k) [0–1]
│       ├─ combined       = kw_weight × keyword_score
│       │                 + sem_weight × semantic_score               (default 50-50)
│       └─ score variants:
│           ├─ score_int   = int(combined × max_points)   ← hard truncation
│           ├─ score_round = round(combined × max_points) ← P1 fix
│           └─ score_float = combined × max_points        ← P2/P3 fix (no truncation)
│
├─ 4. FEEDBACK  (grader/lmql_grading.py::LMQLGrader.grade_with_feedback)
│   ├─ format evidence by criterion
│   ├─ LLM call with LMQL constraints
│   └─ return narrative feedback + source citations
│
└─ 5. OUTPUT  (pipeline.py)
    └─ JSON record (see schema below)
```

### T4.3 benchmark record  (`grading_dynamic_rubrics/results/t4_3/t4_3_run1.json`)

```json
{
  "q01": {
    "good": {
      "question_id": "q01",
      "answer_type": "good",
      "max_score": 10,
      "total_int": 0,
      "total_round": 1,
      "total_float": 2.143,
      "rubric_items": [
        {
          "criterion_id": "conceptual_definitions",
          "max_score": 3,
          "keyword_score": 0.125,
          "semantic_score": 0.200,
          "combined_score": 0.163,
          "score_int": 0,
          "score_round": 0,
          "score_float": 0.488
        }
      ]
    },
    "less_good": { "..." },
    "wrong":    { "..." }
  }
}
```

**Fields explained:**

| Field | Meaning |
|-------|---------|
| `keyword_score` | Fraction of criterion keywords found in student answer |
| `semantic_score` | `min(1, evidence_span_count / semantic_top_k)` |
| `combined_score` | Weighted sum of keyword + semantic |
| `score_int` | `int(combined × max_points)` — collapses ~80% of scores to 0 |
| `score_round` | `round(combined × max_points)` — P1 fix |
| `score_float` | `combined × max_points` — no truncation; used in T4.3 final analysis |
| `found_keywords` | Which rubric keywords were found in the answer |
| `missing_keywords` | Which rubric keywords were absent |
| `citations` | Source document IDs used as evidence |
| `feedback` | LLM-generated narrative with per-criterion explanation |
| `timings` | Wall-clock breakdown by pipeline stage |

## 6. T4.3 Benchmark Results

**Setup:** 5 questions × 3 answer types (good / less_good / wrong) × 2 runs × 3 scoring modes.

**Pass criterion:** `good ≥ less_good ≥ wrong` across both runs and all scoring modes.

| Question | int | round | float | Verdict |
|----------|-----|-------|-------|---------|
| q01 | ✅ | ✅ | ✅ | PASS |
| q02 | ✅ | ✅ | ✅ | PASS |
| q03 | ❌ | ❌ | ❌ | FAIL — less_good < wrong on float |
| q04 | ✅ | ✅ | ✅ | PASS |
| q05 | ❌ | ❌ | ❌ | FAIL — wrong ≥ less_good on round |

**Root causes (from REDESIGN.md §1):**

1. Keyword matching tests vocabulary, not understanding — a student who paraphrases correctly scores 0
2. Semantic score is nearly constant across quality levels (all answer types retrieve similar evidence counts)
3. `int()` truncation collapses low-combined-score answers to 0 regardless of true quality
4. Rubric generated from slides vocabulary; students use web/AI vocabulary → keyword mismatch
5. Stopwords in criterion descriptions dilute keyword signal (partially fixed in P2)

## 7. Key Config Files

| File | Controls |
|------|----------|
| `grading_dynamic_rubrics/config/rubrics.yaml` | question ↔ rubric file mapping |
| `grading_dynamic_rubrics/config/sources.yaml` | index chunking, top_k, reranker model |
| `config/rubric_generation.yaml` | (v2) model tier, evaluation mode, iteration budget |
| `config/llm_config.py` | LLM provider dispatch (Gemini / Ollama) |
| `rubrics_dynamic/yaml/q0N.yaml` | per-question criteria, weights, descriptions |

**Key tuning parameters in `sources.yaml`:**

```yaml
retrieval:
  top_k_per_index: 10
  final_top_k: 5
  similarity_threshold: -1.0   # disabled

reranker:
  model: cross-encoder/ms-marco-MiniLM-L-6-v2
  batch_size: 32

chunking:
  word:     { chunk_size: 512, chunk_overlap: 50 }   # chars; 128 for slides
  sentence: { chunk_size: 256, chunk_overlap: 50 }   # tokens
```

## 8. What V2 Must Add to Match V1 Detail

| V1 Feature | V2 Status | Action needed |
|-----------|-----------|---------------|
| Per-criterion keyword lists (`found` / `missing`) | ❌ removed by design | Replace with per-check concept match evidence |
| Evidence spans cited per criterion | ⚠️ passed to judge, not persisted | Persist evidence chunks in grade JSON |
| Precision-level rationale per check | ⚠️ returned but not saved | Save `CheckEvalV2.rationale` in output |
| Three-way score comparison (int/round/float) | ❌ v2 is float-only by design | Not needed — int/round were diagnostic artifacts |
| Ordering-violation detection | ✅ `v2/benchmark.py` | Done |
| LLM-generated narrative feedback | ❌ not yet in v2 | Add feedback generation step after scoring |
| Source citations in output | ❌ not yet in v2 | Wire `retrieval_core` → `ConceptJudge.evidence_context` |
| Timings per stage | ❌ not yet in v2 | Add timing instrumentation |
| Rubric iteration history | ❌ not persisted | Save each Karpathy iteration's rubric + violations |
| Answer text in grade record | ❌ not in `QuestionResult` | Add `answers: list[SyntheticAnswer]` to output |

**Most impactful gap:** The v1 JSON included the full student answer text, per-criterion
keyword breakdown, and LLM feedback narrative. V2's `QuestionResult` currently records only
convergence status and violation counts — no answer text, no rationale, no feedback.
